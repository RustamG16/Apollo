# Event quality checklist

- Event represents a user or system outcome, not a DOM implementation detail.
- Trigger is unambiguous and testable.
- Properties answer a planned decision and avoid sensitive data.
- Naming matches the existing taxonomy.
- Repeat, back/forward, refresh, and failed-action behavior are specified.
- Consent and retention constraints are known.
- QA can verify the event without polluting production data.
- A dashboard is not created unless someone owns the readout.

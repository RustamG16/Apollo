# 06 — Build plan

Builds Revision B of `04-decision.md`. Single target viewport 1920×1080.

## Stack

| | |
|---|---|
| Build | Vite 7, `@vitejs/plugin-react`, target `es2022` |
| UI | React 19 + TypeScript, strict |
| Motion | `gsap` ^3.13 + `@gsap/react` — ScrollTrigger, Flip, SplitText. All three are free in the standard GSAP licence from 3.13 onward; **verify at install** (defect 23) and record the resolved version here. |
| Fonts | `@fontsource-variable/bodoni-moda`, `@fontsource-variable/archivo`, `@fontsource/jetbrains-mono` — OFL, self-hosted, latin subset |
| Styling | One `src/styles.css`. CSS custom properties as tokens. No framework. |
| Scroll | Native. No Lenis, no ScrollSmoother, no pinning anywhere. |

## The doors — the motion spine

Two absolutely-positioned `<div>`s in `--ground`, `position: fixed`, `inset: 0`, each 50% of
viewport width, one anchored left with `transform-origin: left`, one right with
`transform-origin: right`. Both are `aria-hidden` and `pointer-events: none`.

One ScrollTrigger spans `document.body`, `scrub: 1`, and writes a single progress value to
`--doors` on `:root`. Each panel's `scaleX` is `calc(var(--doors))`, driven by GSAP's
`quickSetter` on `transform` — **transform only, never `clip-path`** (defect 16). Combined
cover runs 94% → 0% monotonically. Nothing else animates during scroll except opacity.

Cover per beat: 94 / 86 / 70 / 60 / 48 / 36 / 0 / 0 / 0. Deltas 8 / 16 / 10 / 12 / 12 / **36**.
The hero's opening is three times the next largest — beat 2 is a passage, not a second hero.

## GSAP ownership map

One owner per element. No element is written by two triggers.

| Owner | Writes | Trigger | Notes |
|---|---|---|---|
| `Doors` | the two panels' `scaleX` | one global ScrollTrigger over `body`, scrub 1 | The only scroll-driven transform on the page |
| `Header` | `--clock` text, `aria-current` on the nav | the same global trigger, via `onUpdate` | Reads progress; writes no transform |
| `Beat0Open` | wordmark characters | SplitText + a one-shot timeline on load, **after `document.fonts.ready`** | Runs once. Never re-runs. |
| `Beat1Street`…`Beat4Hands` | own `opacity` and `y` on entry | one `ScrollTrigger` each, `once: true`, no scrub | Entry only. Not scrub-linked, so they cannot fight the doors. |
| `Beat3Material` | `--field` on its own section | its own trigger, scrub 1 | Ground → `--auburn-deep` over the first 30% of the section |
| `Beat4Hands` | the hunyadi pool's `opacity` | its own trigger, scrub 1 | 0 → 0.55 |
| `Beat5Pass` | Flip state of the plate | React state, **not scroll** | Selection-driven only |
| `Beat6Open` | the vanilla panel's `opacity` and `scaleY` | its own trigger, scrub 1 | A panel, never a full-viewport flood (defect 10) |

Everything else — hovers, focus rings, the dialog — is CSS transition at 150ms.

## Beat 5, the listbox

```
role="listbox" aria-label="Menu"
  role="option" aria-selected  ×6, roving tabindex, one tab stop total
```

All six names permanently visible. Activation on **click, hover, focus, ↑ ↓ Home End**.
Selected option carries an auburn rule plus a text weight change — never colour alone.

On selection: `Flip.getState()` on the plate → swap `src` and the `--pass-field` custom
property → `Flip.from(state, { duration: 0.4, ease: 'power3.out', absolute: true })`.
Both states are 4:3 containers with `object-fit: cover`, so Flip interpolates position and
scale only.

Reduced motion: no Flip. `src` and field swap directly; the list is an ordinary list.

## Reservation dialog

Native `<dialog>` + `showModal()`, so focus trap, `Escape`, backdrop and inertness are the
platform's. Focus moves to the first field on open and returns to the invoking button on
close — `HTMLDialogElement` returns focus itself; verified in QA rather than assumed.

Fields: date, time (**placeholder** — seatings unknown), party size, name, email, note.
Every field has a visible `<label>`. Errors render in text beside the field and in a
`role="alert"` region. No colour-only signalling.

The disclosure — *"This is a prototype. Nothing is sent and no table is held."* — is present
**under the submit button before submission**, and again in the confirmation. Submit sets a
flag. There is no transport, no storage, no logging.

## Fallback matrix

| Condition | Behaviour |
|---|---|
| `prefers-reduced-motion: reduce` | Doors at 0% cover from load. Every beat renders its end state. Clip replaced by `room-poster.webp`. Wordmark set, not animated. No Flip. Nothing invisible, nothing mid-transition. |
| JavaScript disabled | Doors are `scaleX(0)` by default in CSS and only *closed* by JS on load, so no-JS shows the full page, unmasked, all content present. The listbox degrades to a static list showing course 5. The dialog degrades to an anchor to a static reservation section. |
| Video fails or is blocked | Poster image stands. |
| WebP unsupported | Not handled. Every browser this page targets supports WebP; a JPEG tier would be payload for a case that does not occur. |
| Window narrowed below 900px | No designed composition — out of scope. Grid columns collapse via `minmax()`; the page must not overflow horizontally. Verified, not designed. |
| Fonts fail | `font-display: swap` with a real fallback stack. SplitText waits on `document.fonts.ready`, so the wordmark never animates on a fallback face and then reflows. |

## Performance budget

Target 1920×1080 at **240 Hz** — a 4.1 ms frame.

| Metric | Budget |
|---|---:|
| Main-thread scripting per frame during scrub | ≤ 2 ms |
| Scroll-driven properties | `transform` and `opacity` only |
| First view payload (media) | ≤ 2 200 kB · **actual 1 165 kB** |
| JS bundle, gzipped | ≤ 160 kB |
| LCP element | `street.webp`, preloaded, `fetchpriority="high"` |
| Long tasks after load | none during scroll |

`will-change: transform` is set on the two door panels only, and on nothing else — it is a
scarce resource, not a decoration.

## Build order

Static hierarchy first, verified in the browser at 1920×1080, **then** motion. The doctrine
says choreograph before you compose; it does not say animate an unstable layout.

1. Scaffold, fonts, tokens, the contrast table as types.
2. All nine sections with real copy and real images, no motion at all. Screenshot.
3. The doors.
4. Per-beat entries, the auburn field, the hunyadi pool, the vanilla panel.
5. The listbox, then Flip on top of a listbox that already works without it.
6. The dialog.
7. Reduced-motion and keyboard passes, then QA.

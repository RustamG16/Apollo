## Pass 1 findings and repairs

1. **High · hero hierarchy:** The initial desktop reveal left the SAVRA word behind the full-width image. Expected the plan’s monumental word/threshold composition. Repaired by bringing the word into the image plane with a controlled screen blend; verified at 1440×900.
2. **Medium · crossing transition:** Long opacity overlaps produced visible multi-image ghosting. Expected a clean architectural handoff. Repaired with hard rectangular clip wipes between the three stills and video; verified mid-sequence at 1440×900.
3. **Medium · mobile crop:** The first mobile crop lost nearly all of the blue door. Repaired by shifting the mobile focal position toward the door; verified at 390×844.
4. **Medium · document structure:** The visible hero title was not an `h1`. Repaired with a semantic `h1` while preserving the split animation.
5. **Low · mobile menu:** The native horizontal scrollbar used unthemed browser chrome despite visible carousel controls. Hidden on the dish rail while keeping native scrolling, snap, keyboard focus, and controls.
6. **Low · production bundle:** The first asset resolver copied unused alternates and all font language subsets. Replaced with explicit asset URLs and Latin-only font entrypoints.

## Pass 2 independent-review findings and repairs

1. **High · mobile/tablet pin contract:** Crossing and craft ScrollTriggers were still instantiated below 900 px. Repaired by registering every pinned/scrubbed narrative only in the desktop media branch. Browser evidence confirms zero `.pin-spacer` elements at 390×844 and three intended spacers at 1440×900.
2. **Medium · retained evidence:** Added desktop crossing, menu, and dialog captures plus mobile crossing, menu, invitation, and footer captures under `.impeccable/review/`.
3. **Medium · dialog touch target:** Close control now has a 44×44 px minimum hit area.
4. **Low · focus order:** Removed focus stops from non-actionable dish articles; all dish information remains visible and the carousel controls remain keyboard operable.

## Verified behavior

- Production build succeeds with no TypeScript or Vite errors.
- Mechanical interface detector reports `[]`.
- No console warnings or errors were observed.
- Mobile document overflow check: 390 px viewport, 380 px document width, no horizontal document overflow.
- All core regions and dish articles appear in the accessibility tree; the document has one `h1` and ordered `h2`/`h3` structure.
- Reservation opens from persistent navigation, mobile persistent action, conversion interlude, and footer.
- Native dialog receives focus, required fields block empty submission, and the populated prototype reaches its local success state without external transmission.
- Mobile dish controls advance the native snap rail (`scrollLeft` changed from 0 to 318 px).
- Images carry dimensions and descriptive alternatives; decorative texture and transitional duplicate frames are silent.
- Reduced-motion CSS disables transitions/animations, removes long section heights, and the GSAP branch is not instantiated under `prefers-reduced-motion: reduce`. This branch was code-verified; the available browser did not expose media-emulation controls.

## Remaining limitations

- Lighthouse/mobile CPU and network throttling were not available in the connected browser, so the 2.5 s LCP and 200 ms INP targets are guardrails rather than measured claims.
- The 2.18 MB crossing video is the largest payload but remains deferred behind `preload="none"` and an intersection gate.
- Source JPEGs are fixed-dimension, explicitly declared, and lazy below the fold, but responsive AVIF/WebP derivatives are not included; defer this to the deployment image pipeline or the pre-launch task in `09-handoff.md`.
- Restaurant facts and the live reservation provider remain intentionally unresolved.

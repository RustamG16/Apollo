# Asset Director

Treat media as a designed system with purpose, composition, rights, and responsive behavior. Begin only after Gate B.

## Inventory first

Inspect supplied logos, vectors, fonts/licenses, photography, video, product renders, design files, iconography, and brand guidance. Mark each asset as usable, transformable, missing, or rights-unknown.

Prefer, in order:

1. approved existing brand assets;
2. newly supplied first-party media;
3. licensed library media with recorded terms;
4. generated media with explicit approval.

## Write the manifest

For every required asset specify:

- stable ID, purpose, page placement, and message;
- source strategy and owner;
- file format, dimensions/aspect ratio, safe crop, and responsive variants;
- art direction, subject, composition, palette, lighting/material, and exclusions;
- alt text or decorative status;
- rights, license, attribution, and provenance status;
- expected generation quantity/cost and approval state;
- acceptance criteria and fallback.

Use the system `05-asset-manifest.md` template.

## Request useful media

Tell the user exactly what to provide, prioritized as required versus helpful. Avoid vague requests such as “send brand assets.” Name formats, resolution, orientation, duration, and the section each item serves.

## Generate only after approval

If Higgsfield or another media service is available, wait for manifest approval. Generate the smallest representative batch first. Preserve prompt/model/version and rejected-output counts where available. Never claim rights that have not been established.

## Stop

Return the approved manifest and produced file paths. Do not redesign page structure, choose a different concept, or generate speculative filler for undecided sections.
